# 大学生高质量就业画像平台

本平台面向正在了解就业方向、选择目标岗位和规划能力提升路线的大学生。系统基于招聘市场数据，集中展示岗位热度、城市需求、招聘要求、岗位能力画像、工具技术栈以及标准学习路径，帮助学生把“想做什么岗位”进一步拆解为“需要掌握什么、应该先学什么、可以完成哪些实践任务”。

> 当前版本以通信及相关技术岗位为示例数据域。页面展示的是市场统计与标准岗位模型，不代替招聘单位的具体要求，也不构成就业结果承诺。

## 1. 适合谁使用

- 还没有明确就业方向，希望先观察市场需求的学生；
- 已有目标岗位，希望了解岗位职责、专业能力和工具要求的学生；
- 正在多个相似岗位之间选择，希望比较能力差异的学生；
- 希望按照阶段完成学习和实践任务的学生；
- 辅导员、专业教师及就业指导人员，可将统计结果作为教学与指导参考。

## 2. 推荐使用流程

第一次使用时，建议按以下顺序浏览：

1. 在“就业市场”查看近期招聘数量、趋势、城市和招聘门槛；
2. 在“岗位画像”筛选感兴趣的岗位，了解工作范围、能力和工具要求；
3. 在“岗位关系”比较两个相似岗位，确认共同要求和各自特点；
4. 在“学习路径”选择最终目标岗位，按 PB、PF、JP、CP 四个阶段查看实践任务；
5. 打开任务详情，根据任务目标、实施步骤、验收标准和交付成果安排学习。

平台目前提供标准学习路线，不记录个人掌握度、学习打卡、测评成绩或个人进度。

## 3. 进入系统

开发环境默认访问地址为：

```text
http://127.0.0.1:5173
```

打开后会自动进入“就业市场”。顶部导航可切换以下页面：

| 页面 | 地址 | 主要用途 |
| --- | --- | --- |
| 就业市场 | `/market` | 判断市场规模、变化趋势、热门岗位与招聘要求 |
| 岗位画像 | `/roles` | 查看标准岗位的职责、能力和工具技术栈 |
| 岗位关系 | `/relations` | 浏览岗位关联并对比两个岗位的差异 |
| 学习路径 | `/learning` | 查看目标岗位对应的分阶段学习路线与实践任务 |
| 系统管理 | `/admin` | 查看系统数据状态；管理功能目前等待后端接口 |

系统当前没有开放学生注册、登录、找回密码和个人资料功能。

## 4. 就业市场

“就业市场”适合用来回答三个问题：市场上有哪些机会、机会主要在哪里、招聘单位通常要求什么。

### 4.1 使用筛选条件

页面顶部可设置：

- 日期范围：限定招聘数据的统计周期；
- 岗位大类：只观察某一类岗位；
- 城市：比较目标就业城市；
- 招聘平台：查看指定来源的数据；
- 时间颗粒度：按日、周或月观察趋势。

设置后点击“应用筛选”。需要回到默认近 30 天条件时，使用“重置”。筛选项为空通常表示查询全部，不表示无数据。

### 4.2 阅读市场指标

- **通信相关岗位**：当前筛选条件下的岗位样本总量；
- **正在招聘**：当前仍有效的招聘需求；
- **近 7 日新增**：最近 7 天新发布的岗位；
- **近 7 日下架**：最近 7 天停止招聘的岗位；
- **近 7 日净增**：新增数量减去下架数量。

单个数字只反映当前数据范围。判断趋势时，应同时查看日期、城市、数据来源及招聘需求趋势图。

### 4.3 图表与招聘要求

- **招聘需求趋势**：对比在招、新增和净变化，观察需求是否持续；
- **岗位大类分布**：查看不同岗位大类在样本中的数量占比；
- **热门岗位排行**：查看需求量较高的标准岗位及变化率；
- **重点城市**：比较城市在招岗位数量；
- **招聘要求**：在薪资、学历、经验和行业之间切换，了解常见门槛。

百分比表示该条件在当前样本中的占比。样本来源、统计周期或筛选条件改变后，占比也会变化。

### 4.4 导出数据

点击“招聘需求趋势”区域右上角的“导出数据”，浏览器会下载：

```text
就业市场数据-YYYY-MM-DD.xlsx
```

文件包含“招聘趋势”“岗位排行”“城市分析”三个工作表，适合课程报告或个人分析。使用数据时应注明平台、导出日期和筛选范围。

## 5. 岗位画像

“岗位画像”将招聘需求整理为标准岗位模型，用于回答“这个岗位做什么、需要哪些能力、常用哪些工具”。

### 5.1 查找岗位

- 使用“岗位大类”缩小列表范围；
- 在搜索框输入岗位名称、所属方向或职责关键词；
- 从左侧岗位列表选择目标岗位；
- 岗位卡片会显示在招数量、能力数量和工具数量。

### 5.2 阅读岗位详情

- **工作范围**：岗位通常负责的业务与工作边界；
- **专业能力结构**：完成岗位工作所需的能力单元；
- **微能力**：能力单元下更具体、可学习和可训练的能力项；
- **工具与技术栈**：招聘和实践中常见的软件、平台、语言或工程工具；
- **相似岗位**：能力接近但职责侧重点不同的岗位。

点击“查看学习路径”可带着当前岗位直接进入学习路径页面。点击相似岗位可快速切换画像。

### 5.3 W 与 R 的含义

- **W（支撑权重）**：某项能力对目标岗位的支撑程度。数值越高，越应优先掌握；
- **R（工具要求度）**：目标岗位对某项工具或技术栈的要求程度。数值越高，通常意味着使用频率或重要性更高。

W 和 R 是基于平台规则和数据计算得到的岗位级指标，用于安排学习优先级。它们不是个人考试分数，也不表示录用概率。

## 6. 岗位关系与岗位对比

“岗位关系”页面由两个部分组成：

### 6.1 关系图谱

- 每个节点代表一个标准岗位；
- 连线表示岗位之间存在易混淆、职责相关或能力相近关系；
- 可拖动、缩放图谱，悬停连线查看关系说明；
- 数据异常或更新后，可点击“刷新图谱”重新加载。

### 6.2 两岗对比

分别选择岗位 A 和岗位 B，点击“开始对比”，页面会展示：

- 两个岗位各自的工作范围；
- 共同能力、岗位 A 特有能力、岗位 B 特有能力；
- 共同工具及双方特有工具。

建议先比较共同基础，再判断自己更愿意补齐哪一侧的特有能力。不能选择同一个岗位进行自我对比。

## 7. 学习路径

“学习路径”用于把岗位要求转换为可执行的学习与实践顺序。

### 7.1 选择目标岗位

在页面顶部搜索并选择标准岗位。若从岗位画像点击“查看学习路径”进入，系统会自动选择对应岗位。

页面会展示任务总数、主任务数、补充任务数，以及五项覆盖指标：

- 综合覆盖；
- 微能力加权满足度；
- 核心微能力通过率；
- 工具加权满足度；
- 核心工具通过率。

这些指标描述标准路线对岗位要求的覆盖程度，不代表当前学生本人已经掌握的程度。

### 7.2 四阶段路线

| 阶段 | 作用 |
| --- | --- |
| PB | 公共基础，建立通用知识和基本操作能力 |
| PF | 专业基础，形成岗位方向所需的专业能力 |
| JP | 岗位实践，通过较完整的任务训练岗位技能 |
| CP | 综合实践，完成更接近真实工作场景的综合交付 |

每个阶段包含“主任务”和“补充任务”。主任务构成路线主体，补充任务用于补足特定能力或工具要求。

### 7.3 实践任务详情

点击任务卡片后，右侧抽屉会展示：

- 工程背景和任务目标；
- 任务内容及建议实施步骤；
- 每一步的验收标准；
- 能力训练贡献 T；
- 工具提升度 d；
- 最终需要形成的交付成果。

建议按照“理解背景 -> 完成步骤 -> 对照验收 -> 整理成果”的顺序执行任务，并将代码、报告、演示材料或实验记录保留为作品集证据。

### 7.4 T 与 d 的含义

- **T（训练贡献）**：某项实践任务对具体微能力的训练贡献；
- **d（工具提升度）**：完成任务后，对特定工具熟练度的预期提升程度。

T 和 d 用于说明任务价值，不是学生个人完成任务后自动获得的分数。

## 8. 数据状态说明

页面会显示当前数据模式和更新时间：

- **Mock 模式**：使用仓库内的演示数据，适合界面体验和前端开发；
- **真实接口模式**：数据来自已配置的后端服务；
- **数据更新时间**：表示后端最近一次数据刷新时间，不一定等于当前访问时间。

招聘信息存在发布时间、下架时间、平台去重和分类误差。做职业判断时，建议结合招聘网站原始岗位、企业官网、学校就业信息和真实从业者反馈交叉验证。

## 9. 常见问题

### 页面提示“无法连接数据服务”

真实接口模式下，请确认后端服务已启动、接口地址正确且网络可访问。仅体验页面时可以切回 Mock 模式。

### 页面一直显示 Mock 数据

环境变量 `VITE_USE_MOCK` 只有精确设置为 `false` 才会请求真实后端。修改环境变量后需要重新启动前端开发服务器。

### 筛选后没有数据

先扩大日期范围或清空岗位、城市和平台筛选。若仍无数据，可能是当前条件确实没有样本，或后端数据尚未更新。

### 百分比为什么与招聘网站不完全一致

平台按当前入库、清洗、去重和岗位分类后的样本计算。统计口径、更新时间和筛选范围不同，结果会不同。

### 为什么没有个人进度或推荐结果

当前版本提供标准岗位画像和标准学习路线，尚未接入学生账户、个人能力测评、学习记录和个性化推荐。

### 手机能否使用

页面支持常见移动端宽度，但关系图谱、复杂对比和大规模图表更适合在电脑端查看。

## 10. 数据与隐私边界

- 学生端当前不采集姓名、学号、联系方式、简历或测评结果；
- 平台不直接连接招聘网站账号，也不会替学生投递简历；
- 导出的 XLSX 文件保存在用户本机，请自行管理和合理引用；
- 招聘数据的采集、清洗、授权和更新由后端或独立数据服务负责，前端只展示处理结果。

## 11. 开发者快速启动

正式前端位于 `frontend/`，采用 Vue 3、TypeScript、Vite、Vue Router、Pinia、Axios、Element Plus、ECharts、Day.js、SheetJS 和 SCSS。

建议使用 Node.js 20.19 或更高版本，并安装 pnpm。

```bash
cd frontend
pnpm install
pnpm dev
```

默认启用 Mock 数据，访问 `http://127.0.0.1:5173` 即可使用。

连接真实后端时，将 `frontend/.env.example` 复制为 `frontend/.env.local`，并设置：

```env
VITE_API_BASE_URL=http://127.0.0.1:18100
VITE_USE_MOCK=false
VITE_REQUEST_TIMEOUT=15000
```

常用检查命令：

```bash
pnpm run typecheck
pnpm run lint
pnpm run build
pnpm run preview
```

后端联调、页面接口矩阵和部署约定见 [`docs/后端联调交接说明.md`](docs/后端联调交接说明.md)。接口字段的正式合同见 `前端接口交付包/openapi.json`。
