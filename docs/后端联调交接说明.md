# 后端联调交接说明

本文档面向接手数据服务、接口实现和部署联调的后端开发者。内容以当前 `frontend/` 实际代码为准；字段类型和完整示例以 `前端接口交付包/openapi.json` 为正式合同。

## 1. 工程概况

- 前端工程：`frontend/`
- 前端框架：Vue 3 + TypeScript + Vite
- 路由与状态：Vue Router 4 + Pinia
- HTTP 客户端：Axios
- UI 与图表：Element Plus + ECharts
- 日期与导出：Day.js + SheetJS/XLSX
- 样式：SCSS
- 接口数量：学生端 15 个接口
- 请求方式：全部为 `POST`
- 请求格式：`application/json`
- 字段命名：`snake_case`

关键实现位置：

| 内容 | 文件 |
| --- | --- |
| 接口路径常量 | `frontend/src/api/endpoints.ts` |
| Axios、Mock 和错误处理 | `frontend/src/api/client.ts` |
| 请求参数组装 | `frontend/src/api/services.ts` |
| TypeScript 接口类型 | `frontend/src/types/api.ts` |
| 正式接口合同 | `前端接口交付包/openapi.json` |
| 请求及返回样例 | `前端接口交付包/mock_data/` |

## 2. 端口与地址

| 服务 | 默认地址 | 说明 |
| --- | --- | --- |
| 前端开发服务器 | `http://127.0.0.1:5173` | Vite 固定监听 `127.0.0.1:5173` |
| 后端 API | `http://127.0.0.1:18100` | 前端环境变量和 Vite 代理的默认目标 |
| 前端 API 代理 | `http://127.0.0.1:5173/api/*` | Vite 转发到 `http://127.0.0.1:18100/api/*` |
| 构建预览 | Vite 自动分配，通常为 `http://127.0.0.1:4173` | 以终端输出为准 |

开发期推荐同源代理：`VITE_API_BASE_URL` 留空时，浏览器请求 `/api/*`，由 Vite 代理至 18100 端口，可避免本地 CORS 问题。

当前 `.env.example` 显式设置了 `VITE_API_BASE_URL=http://127.0.0.1:18100`。采用该配置时浏览器会跨端口直连后端，后端必须允许 `http://127.0.0.1:5173` 跨域访问。

## 3. 环境要求

- Node.js 20.19 或更高版本；
- pnpm；
- 可选：运行在 18100 端口的后端服务；
- Windows PowerShell、CMD、Git Bash 或其他常用终端均可。

首次安装：

```bash
cd frontend
pnpm install
```

## 4. 启动方式

### 4.1 仅启动前端 Mock

Mock 模式不依赖后端，适合核对页面和返回数据形态。

```bash
cd frontend
pnpm install
pnpm dev
```

默认 `VITE_USE_MOCK=true`。打开 `http://127.0.0.1:5173`。

### 4.2 连接真实后端

1. 启动后端并确认 `http://127.0.0.1:18100` 可访问；
2. 将 `frontend/.env.example` 复制为 `frontend/.env.local`；
3. 修改环境变量；
4. 启动或重启前端。

```env
VITE_API_BASE_URL=http://127.0.0.1:18100
VITE_USE_MOCK=false
VITE_REQUEST_TIMEOUT=15000
```

```bash
cd frontend
pnpm dev
```

注意：`VITE_USE_MOCK` 只有字符串值精确为 `false` 时才会请求后端。Vite 在启动时读取环境变量，修改后必须重启。

### 4.3 使用 Vite 同源代理

希望避免开发期 CORS 配置时，可将基础地址留空：

```env
VITE_API_BASE_URL=
VITE_USE_MOCK=false
VITE_REQUEST_TIMEOUT=15000
```

此时 `/api` 请求会由 `frontend/vite.config.ts` 代理至 `http://127.0.0.1:18100`，路径不重写。

### 4.4 构建与质量检查

```bash
cd frontend
pnpm run typecheck
pnpm run lint
pnpm run build
pnpm run preview
```

生产构建输出目录为 `frontend/dist/`。

## 5. 页面细节与接口矩阵

应用启动时，根布局会并行加载 3 个公共接口。之后各页面按需请求业务接口。

### 5.1 公共初始化

| 接口 | 固定请求体 | 页面用途 |
| --- | --- | --- |
| `/api/v1/system/bootstrap/query` | `{"include_module_status":true}` | 系统名称、API 版本、数据模式、默认筛选、模块状态、刷新状态 |
| `/api/v1/taxonomy/tree/query` | `{"active_only":true}` | 岗位大类、方向、标准岗位树；驱动下拉框和岗位选择 |
| `/api/v1/market/filter-options/query` | `{"include_platforms":true}` | 城市、平台、岗位状态、颗粒度和可用日期范围 |

三个接口通过 `Promise.all` 并发请求。任一接口失败会导致公共初始化失败，因此后端应保证它们可独立、快速返回。

### 5.2 就业市场 `/market`

页面细节：

- 顶部筛选日期、岗位大类、城市、招聘平台及日/周/月颗粒度；
- 展示样本总量、在招、近 7 日新增、下架和净变化；
- 展示趋势图、岗位大类分布、热门岗位、重点城市；
- 招聘要求支持薪资、学历、经验、行业切换；
- 前端导出趋势、岗位排行和城市分析为 XLSX，不请求导出接口。

点击“应用筛选”或“重置”后，以下 6 个接口并行请求：

| 接口 | 请求体附加字段 | 使用结果 |
| --- | --- | --- |
| `/api/v1/market/overview/query` | `{ filters }` | 5 项概览指标 |
| `/api/v1/market/trend/query` | `options.granularity`、`options.limit=30`、`compare_previous_period=true` | 在招、新增、下架、净变化趋势 |
| `/api/v1/market/role-distribution/query` | `taxonomy_level="family"` | 岗位大类饼图 |
| `/api/v1/market/role-ranking/query` | `ranking_type="demand"`、`limit=10` | 热门岗位与变化率 |
| `/api/v1/market/city-analysis/query` | `options.granularity`、`options.limit=10` | 城市在招数量图 |
| `/api/v1/market/requirements/query` | `dimensions=["salary","education","experience","industry","company"]` | 招聘要求分布 |

公共 `filters` 结构：

```json
{
  "date_from": "2026-09-01",
  "date_to": "2026-09-16",
  "family_codes": [],
  "direction_codes": [],
  "role_codes": [],
  "city_codes": [],
  "platform_codes": [],
  "job_status": "active"
}
```

数组为空表示不限制该维度。日期格式为 `YYYY-MM-DD`，起止日期均包含当天，按 `Asia/Shanghai` 解释。

### 5.3 岗位画像 `/roles`

页面细节：

- 岗位大类支持多选；
- 关键词搜索在前端本地执行，搜索岗位名称、方向名称和工作范围；
- 岗位卡片展示在招数量、能力数、工具数；
- 详情展示工作范围、W 支撑权重、微能力、R 工具要求度和相似岗位；
- “查看学习路径”跳转 `/learning?role={role_code}`。

| 接口 | 请求体 | 触发时机 |
| --- | --- | --- |
| `/api/v1/roles/map/query` | `{"family_codes":[],"direction_codes":[]}` | 页面进入或岗位大类变化 |
| `/api/v1/roles/profile/query` | `{"role_code":"P1.1.1"}` | 选中岗位；可选 `market_filters` 当前未传 |

岗位地图返回非空时，前端默认选择第一项并请求其画像。后端应保持岗位编码在分类树、岗位地图、画像、关系和学习路径中一致。

### 5.4 岗位关系 `/relations`

页面细节：

- ECharts 力导向图展示岗位节点和关系边；
- 悬停关系边时显示 `relation_type` 和 `summary`；
- 两个岗位下拉框来自公共岗位分类树；
- 对比结果展示工作范围、共同/特有能力和共同/特有工具。

| 接口 | 请求体 | 触发时机 |
| --- | --- | --- |
| `/api/v1/roles/relations/query` | `{"family_codes":[],"direction_codes":[],"role_codes":[]}` | 页面进入或点击刷新 |
| `/api/v1/roles/compare` | `{"role_code_a":"P1.1.1","role_code_b":"P1.1.2"}` | 页面进入时默认对比，或用户点击“开始对比” |

节点编码必须与边的 `source_role_code`、`target_role_code` 对应。前端会阻止两个相同岗位的对比。

### 5.5 学习路径 `/learning`

页面细节：

- 可搜索分类树中的全部标准岗位；
- 展示总任务、主任务、补充任务和 5 项覆盖率；
- 按 PB、PF、JP、CP 四阶段展示主任务和补充任务；
- 点击任务后，以右侧抽屉展示工程背景、目标、步骤、验收标准、T、d 和交付成果。

| 接口 | 请求体 | 触发时机 |
| --- | --- | --- |
| `/api/v1/learning-path/query` | `{"role_code":"P1.1.1"}` | 页面进入或切换目标岗位 |
| `/api/v1/practice-tasks/detail/query` | `{"task_code":"..."}` | 点击任务卡片 |

覆盖率字段范围为 0 到 1，前端乘以 100 后显示。`stage_code` 仅接受 `PB`、`PF`、`JP`、`CP`；建议后端按 `stage_order` 升序返回。

### 5.6 系统管理 `/admin`

当前页面只展示系统数据状态和以下待接入模块：

- 用户与角色；
- 岗位数据管理；
- 统计任务；
- 操作日志。

这些模块目前没有可操作表格、表单、权限路由或 CRUD 请求，现有 15 个接口中也没有管理端接口。后端不应把本页面视为已完成的管理系统。待确定登录鉴权、角色权限和数据维护流程后，需要另行设计接口并补充前端。

## 7. 统一响应约定

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "meta": {
    "request_id": "uuid",
    "generated_at": "2026-09-16T10:00:00+08:00",
    "data_updated_at": "2026-09-16T08:00:00+08:00",
    "timezone": "Asia/Shanghai"
  }
}
```

业务失败响应：

```json
{
  "code": 40001,
  "message": "请求参数无效",
  "data": null,
  "meta": {
    "request_id": "uuid"
  }
}
```

前端判定规则：

- `code === 0` 且 `data !== null` 才视为成功；
- `code !== 0` 或 `data === null` 会抛出业务错误；
- 后端 `message` 会直接用于页面错误提示，应返回可理解且不泄露内部信息的文本；
- `meta.request_id` 应始终提供，便于根据前端报错定位后端日志；
- 请求超过 `VITE_REQUEST_TIMEOUT` 时，前端显示超时提示；
- 没有收到 HTTP 响应时，前端显示“无法连接数据服务”。

建议 HTTP 状态码与业务结果保持一致：成功使用 2xx，参数问题使用 4xx，服务异常使用 5xx。即使 HTTP 非 2xx，若能返回统一响应体，前端仍可提取 `message` 和 `request_id`。

## 8. 数据字段与计算责任

- 所有接口字段使用 `snake_case`；
- 日期使用 `YYYY-MM-DD`；时间使用带时区的 ISO 8601；
- 比例和变化率返回 0 到 1 的小数，例如 `0.235` 表示 `23.5%`；负增长可返回负数；
- 无列表数据返回 `[]`，不要返回 `null`；
- OpenAPI 声明可空的单值字段可返回 `null`；
- 数量字段返回 number，不要返回带逗号或单位的字符串；
- 分类、方向、岗位、任务和工具编码应跨接口稳定一致；
- 排行、阶段、步骤等有顺序的数据应按业务顺序返回；
- W、R、T、d 及其中文标签由后端根据统一口径计算，前端只格式化和展示，不重复计算；
- `data_updated_at` 表示数据实际更新时间，`generated_at` 表示本次响应生成时间，两者不要混用。

## 9. CORS 与代理要求

前端跨域直连 `http://127.0.0.1:18100` 时，后端至少应允许：

```text
Origin: http://127.0.0.1:5173
Methods: POST, OPTIONS
Headers: Content-Type, Accept
```

如开发人员使用 `http://localhost:5173`，需一并加入允许来源，或统一要求访问 `127.0.0.1`。当前接口没有携带 Cookie 或 Authorization 头；后续接入 JWT/Token 时，需要同步更新 CORS 允许头和 Axios 请求拦截器。

生产环境建议由 Nginx 同域托管静态文件并反向代理 `/api/`，避免公开后端内部端口：

```text
浏览器 -> https://example.com/       -> frontend/dist/
浏览器 -> https://example.com/api/   -> backend:18100/api/
```

使用 Vue Router history 模式，Nginx 必须将非静态文件的前端路由回退到 `index.html`，否则刷新 `/market`、`/roles` 等地址会返回 404。

当前交付不包含以下接口，不能假定前端已经支持：

- 登录、退出、Token 刷新、注册和找回密码；
- 用户列表、账号状态和角色分配；
- 招聘原始数据增删改查及审核；
- 岗位分类、能力、工具和学习任务的管理端维护；
- 爬虫任务触发、数据清洗状态和统计重算；
- 操作日志与审计查询；
- 学生个人画像、能力测评、收藏、打卡和学习进度；
- 服务端 XLSX 导出。

新增上述能力前，应先确认权限模型、数据表、分页结构、错误码和审计要求，再扩展 OpenAPI 与前端类型。

## 12. 常见联调问题

### 浏览器没有发出请求

检查 `VITE_USE_MOCK` 是否仍为 `true`，并在修改 `.env.local` 后重启 Vite。

### 请求地址出现重复 `/api`

接口路径已经以 `/api/v1/...` 开头。`VITE_API_BASE_URL` 应填写主机和端口，例如 `http://127.0.0.1:18100`，不要填写 `http://127.0.0.1:18100/api`。

### 后端可访问但浏览器报跨域

直接在浏览器打开接口不能验证 CORS。检查 `OPTIONS` 预检响应和 `Access-Control-Allow-Origin`，或改用 Vite 同源代理。

### HTTP 200 但页面显示错误

检查统一响应体的 `code` 是否为 0、`data` 是否为非 null，以及字段名是否符合 OpenAPI。Mock 文件保存的是 `data` 部分，真实后端必须再包统一响应外层。

### 图表为空但接口有响应

检查列表字段是否返回 `[]` 或正确数组，比例是否为 number，并确认字段名称与 `frontend/src/types/api.ts` 一致。

### 页面首次进入整体初始化失败

公共 3 个接口是并发且共同初始化的。依次检查 `bootstrap/query`、`taxonomy/tree/query` 和 `filter-options/query`，任一失败都会影响全局筛选及岗位列表。

## 13. 交接依据与变更原则

联调时按以下优先级判断约定：

1. `前端接口交付包/openapi.json`：字段、必填项和响应结构的正式合同；
2. `frontend/src/api/services.ts`：当前页面实际发送的请求参数；
3. `frontend/src/types/api.ts`：当前页面实际消费的数据字段；
4. `前端接口交付包/mock_data/`：有数据与空数据示例；
5. 本文档：运行方式、页面行为和联调流程说明。

接口发生变化时，应同时更新 OpenAPI、Mock、TypeScript 类型、服务层和本文档，避免页面实现与合同分离。
